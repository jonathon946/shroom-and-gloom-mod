# Reconnaissance — Shroom and Gloom

## The game

- **What it is:** a first-person roguelike "double deckbuilder" by Team Lazerbeam, published by Devolver Digital. One deck is for exploring tunnels (navigating, modifying cards, unlocking things), one for combat. Enemies are cooked and eaten to heal. Press coverage: [Gematsu announcement](https://www.gematsu.com/2025/05/first-person-roguelike-double-deckbuilder-shroom-and-gloom-to-be-published-by-devolver-digital), [Wikipedia](https://en.wikipedia.org/wiki/Shroom_and_Gloom).
- **Installed build:** game version 0.6.41 (from `LoadTimings.log`), Steam app 3271280, buildid 25442225. Early Access.
- **Engine:** Unity 2022.3.62f3, **IL2CPP** (`GameAssembly.dll`, 56 MB; `global-metadata.dat` version 31, 20 MB). There is no `Managed` folder. 64-bit, Direct3D 11.
- **Anti-cheat:** none seen. Single-player. Native plugins are only Steamworks, SQLite, Burst and Sentry (crash reporting).
- **No mod loader and no accessibility mod** is installed, and a web search on 2026-10-11 found no existing accessibility mod for this game.
- **No screen-reader library ships with the game.** `UnityEngine.AccessibilityModule` is in the assembly list, but that is a stock Unity module and not evidence of support.

## Libraries the game uses (from `ScriptingAssemblies.json`)

- **UI:** uGUI (`UnityEngine.UI`) with TextMeshPro. UI Toolkit is present as a module but the game's own screens look uGUI-based (unverified until a loader runs).
- **Text effects:** Febucci Text Animator (typewriter text). Read the source string, never the animated visible text.
- **Input:** the new Unity Input System (`Unity.InputSystem`), with a generated `ShroomyInputActions` class and rebinding screens. Legacy input is also present.
- **Localisation:** Unity Localization with Addressables. String tables exist for English, German, Russian, Simplified Chinese and Brazilian Portuguese (full size), and French, Japanese, Portuguese and Spanish (small, so probably partial). The bundles are LZ4-compressed; read text at run time through the game's own `S_Localization` / `LocalizedString` rather than from the files.
- **Other:** DOTween, UniTask, MoreMountains Feedbacks, Newtonsoft.Json, SQLite (the stats database `game.stats`), Unity Visual Scripting, NodeGraphProcessor, Steamworks.NET.

## The game's own structure (from class and file names in the metadata)

The metadata keeps the developers' real names: about 148,000 identifiers and about 4,600 source file names (game and third-party). `tools/Dump-MetadataNames.ps1` writes them to `reference/`. Names are evidence of what exists, not of how it behaves.

- **Naming scheme:** `S_` is a singleton manager, `M_` a model, `V_` a view. Model and view are separate, which is good for us: state can be read from models without scraping the screen.
- **Managers:** `S_BootManager`, `S_ControllerFocus`, `S_InputManager`, `S_Localization`, `S_EnemyEncounterManager`, `S_IntentRouter`, `S_WorldStateManager`, `S_QuestManager`, `S_SaveManager`, `S_GameSettingsManager`, `S_InitialTutorial`, `S_MapReminder`, `S_RewardClaimedUIManager`, `S_PlayerValuesDisplay`, `S_AutoPlay`.
- **Cards and hands:** `M_CardInstance`, `M_GameplayCardInstance`, `M_ForesightCardInstance`, `M_Deck`, `M_GameplayDeck`, `M_Hand`, `M_GameplayHand`, `M_ForesightHand`, with matching `V_` views. Card data: `CardProperty`, `CardTrigger`, `CardIntent`, `CardTag`, `CardDeckType`, `CardTargetCast`, `CardTargetSet`, `OrableCard`.
- **Combat:** `M_Enemy`, `M_EnemyController`, `M_Hazard`, `M_Player`, `CombatRoom`, `CombatLane`, `CombatLaneController`, `EndPlayerTurnButton`, `StatusEffect`, about 25 `*EnemyIntent` classes (deal damage, block, curse, steal card, reinforcements, retreat and so on), `EnemyIntentDisplay`, `EnemyHealthDisplay`, `EnemyStatusDisplay`, `PlayerHealthData`.
- **A combat event log already exists:** `CombatEventLog`, `CombatEventLogFacade`, `CombatEventRecord`, `CombatEventKind`. There is also a `GameplayEventType` enum with `CardDiscovered`, `CardChosen`, `CardTriggered`, `EnemyIntentPlayed`, `HazardIntentPlayed`, `EnemyDeath`, `HazardDeath`, `EnemyDamaged`, `PlayerDamaged`, `TunnelDiscovered`, `CampStructurePlaced`, `ExploreInteractionDiscovered`. One of these is the likely source for spoken combat events.
- **Encounters:** `EncounterType` includes `AdditiveUnlockCamp`, `BowlShop`, `CardChoice`, `ForesightChoice`, `LootAll`; each has an `*EncounterUI` class (also `ModifyCardEncounterUI`, `DeckUnlockEncounterUI`, `TrophyShelfEncounterUI`, `GeneralEncounterUI`).
- **World and map:** `MapUIController`, `MapAct`, `MapPath`, `MapSegment`, `MapRewards`, `PathSelectionNode`, tunnels (`TunnelSettings`, `TunnelPathSettings`), doors (`Door`, `GatewayDoor`, `PortalDoor`, `BaseDoorLock`), `ExploreRoom`, `CampManager`.
- **Inspect and tooltips:** `InspectPanel`, `InspectPanels`, `CardInspectSubject`, `EnemyInspectSubject`, `InspectKeywordSection`, `InspectTooltipSection`, `KeywordTooltipRegistry`, `KeywordStatusEffectRegistry`, `KeywordEnemyIntentRegistry`, `KeywordIntentDescriptionRegistry`, and methods such as `GetIntentToolTipText` and `GetStatusToolTipKey`. The game can already describe a card, an enemy, an intent and a keyword in text.
- **Menus:** `TitleScreen`, `TitleScreenMenu`, `MainMenuCanvas`, `SettingsMenu`, `GameSettingsUI`, `TabMenuUI`, `ControlsTabUI`, `DialogUI`, `DeckDisplay`, `RunModifiersUI`, `QuestCompletePopup`.

## The most important finding: the game has a controller focus system

A `ControllerNav` namespace implements focus navigation for gamepad play across the whole game:

- `IControllerFocusTarget` (`Focus`, `Unfocus`, `IsFocusable`, `FocusWorldPosition`), `IControllerFocusInteractable`, `IControllerFocusHand`.
- `IFocusScope` (`IsActive`, `IsShown`, `Sections`, `Targets`, `FocusEntryTarget`, `Cancel`, `AllowsCardTargeting`), `MenuFocusScope`, `FocusScopeRegistry`, `FocusStack`, `FocusGraph`.
- Section types for every kind of control: `FocusButtonSection`, `FocusCardRowSection`, `FocusSliderSection`, `FocusDropdownSection`, `FocusTabSection`, `FocusRebindSection`, `FocusPathColumnSection`, `FocusValueSection`, `FocusItemSection`.
- `FocusMode` values `Free`, `List`, `Mixed`, `Suppressed`, `Rebinding`; a `FocusExclusion` enum (`Dead`, `NotFocusable`, `OutOfRange`, `Gated`, `OutOfScope`); `CombatFocusRule`; `HandFocusResolver`.
- `S_ControllerFocus` and `ControllerFocusRegistry` hold the current focus.

**Why it matters.** The hard part of most accessibility mods is inventing a keyboard cursor over a mouse-driven game. Here the developers have already built one for gamepads, covering menus, the hand, enemies and world objects. The likely shape of the mod is: hook focus changes, describe whatever was focused using the model and the inspect and tooltip text, and add query keys. Two things are unverified until code runs in the game: whether keyboard keys can drive this focus system (or only a gamepad), and whether every screen is covered.

## Prism

- **What and where:** [ethindp/prism](https://github.com/ethindp/prism), MPL-2.0, a C library with one API over NVDA, JAWS, SAPI, OneCore, UI Automation notifications, ZDSR and others. Current release v0.18.3 (2026-09-30). The Windows package is `prism-windows-x64.zip`; `dynamic/release/bin/prism.dll` is the only binary needed and it has no extra runtime DLLs. Ship its `LICENSES/` and `NOTICE` with it.
- **What the Dwarf Fortress mod did** (Session 18, 2026-10-10, commit `a5f345d`): Tolk was planned there but never built; Prism replaced the plan. Because DFHack's Lua has no FFI, a small C shim loads `prism.dll` by full path and calls it. The header is vendored at `../dwarf-fortress-accessibility/dfhack/bridge/deps/prism.h`. The copy of `prism.dll` there is v0.18.3, 1,212,416 bytes, SHA256 `7C7D09C8C7306E8E1A0C46D603CCB2A391C194C77843400C11B746E7DD56A467`.
- **We do not need a shim.** A C# mod calls Prism directly with P/Invoke. Four installed C# mods already do (Say the Spire 2, Songs of Conquest Access, Harkest Dungeon, OniAccess), none through a wrapper library. A third-party binding, [qt06/prism.net](https://github.com/qt06/prism.net), exists but is not on NuGet and has not been evaluated.
- **Smallest working sequence** (as Harkest Dungeon does it): load `prism.dll` by absolute path; `prism_init(NULL)`; `prism_registry_create_best(ctx)`; `prism_backend_initialize(backend)`, treating `PRISM_ERROR_ALREADY_INITIALIZED` as success; then `prism_backend_output(backend, utf8Text, interrupt)` (speech and braille) or `prism_backend_speak`; `prism_backend_stop` to silence; on exit `prism_backend_free` then `prism_shutdown`.
- **Marshalling:** calling convention Cdecl; text as a null-terminated UTF-8 byte array; `bool` is one byte (`UnmanagedType.I1`); backend names come back as UTF-8 `char*`. Prism rejects invalid UTF-8. Take enum values from `prism.h`, not from another mod (Say the Spire 2's error enum is in a different order).
- **Known caveats:**
  - With NVDA 2026.2, Prism's NVDA backend cannot report "still speaking" (the feature flag is off at run time). The Dwarf Fortress mod needed that for paced speech and so keeps NVDA on NV Access's own client. We only need it if we pace speech; plain speak and interrupt work through Prism.
  - A backend instance is not thread-safe: make every call from one thread or under one lock.
  - Say the Spire 2's changelog records some users reporting lag after its move to Prism, and it re-added Tolk as an option. Watch for latency in the first ear test.
  - The Prism builds shipped with the other mods are older than 0.18.3 and all differ; do not borrow a DLL from another game, fetch the release.

## The loader question (not yet answered)

The mod needs a loader that can start under Unity 2022.3.62f3 IL2CPP and generate interop assemblies from metadata version 31.

- **MelonLoader 0.7.x** is the pattern proven on this machine, but only on Unity 6. [MelonLoader issue 1063](https://github.com/LavaGang/MelonLoader/issues/1063) reported a crash at start during IL2CPP initialisation on Unity 2022.3.62f2 with MelonLoader 0.7.1. It was closed as stale on 2026-03-30 with no fix named. The Class of '09 project's `docs/known-issues.md` recorded the same report and says BepInEx 6 Bleeding Edge crashed too.
- **BepInEx 6 Bleeding Edge:** older builds rejected metadata 31 ("We support 23-29, got 31", [issue 952](https://github.com/BepInEx/BepInEx/issues/952)); build be.753 and later report a supported range of 23 to 31, and a be.755 report shows a Unity 2022.3.64f1 game getting as far as downloading its Unity libraries ([issue 1295](https://github.com/BepInEx/BepInEx/issues/1295)).
- **Neither is confirmed for this exact Unity build.** This is the killer assumption and Spike 1 in the plan. Darkest Dungeon II on this machine runs Unity 2022.3.62f2 under BepInEx 5, but on Mono, which says nothing about IL2CPP.
