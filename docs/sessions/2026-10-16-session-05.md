# Session 05 — 2026-10-16 — lag that grows through a run

## What was reported

The tester Leanne played v0.1.1 up to the second boss. Fights were much smoother after the update, but the further she played, the more lag crept in, for instance moving between cards in a camp and choosing rewards. The maintainer asked whether something builds up the longer a run goes on.

## What was found

- Game build 25442225, the same as verified; no reference regeneration needed.
- The mod's own lists (history, seen things, enemy names, message times) are all capped or cleared; none of them grows without limit.
- Two parts of the mod still searched the whole game world on a timer outside fights: the proximity assist (`WorldAssist`, every 0.25 s) and the end-of-run card pack search (`Rewards`, every 0.5 s). Part 12 of Session 04 had only switched them off in fights, which is why fights improved while camps and reward screens did not.
- The dev log of 2026-10-14 17:09 (`MelonLoader\Logs\26-10-14_17-9-32.log` in the game folder) shows the growth directly. On the card-reward screen, with no scene loaded in between, those two parts went from about 1 ms to 9–16 ms a frame in five minutes. The game's frame time went from 65 to 94 ms over the same period.
- A count of loaded objects (new dev command `count`) on the same screen was flat at 15,535 for four minutes, so the game is not piling up objects. Why a scene search grows slower over time is not known; it is recorded as such in the lessons.

## What was done

- `WorldAssist.cs`: the gates come from the game's own `ControllerFocusRegistry._targets` and `GatesFor`, not a scene search. If the registry cannot be read (a game update), it logs that once and falls back to the old search every 2 seconds. The log says how many targets, gated targets and unseen gates there are when that changes.
- `Rewards.cs`: the pack is looked for only in the scene where the end-of-run page (`RoundUpUIManager`) has opened.
- `Perf.cs`: the 30-second `[perf]` line ends with the game's heap used and reserved, its collection count, and the mod's heap and collection count.
- `DevBridge.cs`: `count` logs the number of loaded objects and the most repeated names (dev only).
- `paste-commands.ps1`: checklist item O, and how Leanne can send a log if lag still creeps in.

## Verified by data / unverified

- **Verified by data** (dev runs, game in the background):
  - The registry holds the backpack's gate in the tutorial (snapshot `backpack-start-2026-10-14`: "3 targets, 1 gated, 1 unseen", then 0 unseen). This time the game marked it seen itself.
  - In a deep-run tunnel (snapshot `far-run-tunnel4`), WorldAssist no longer appears among the costly parts.
  - On the reward screen after a fight (snapshot `tunnel1-first-fight`, `dev:killall`, 5.5 minutes with arrow presses), the mod held steady at 1.1–1.5 ms a frame, against a climb to 9–16 ms before. The game held at 54–59 ms a frame, against 73–94 ms before. The game's heap stayed between 99 and 114 MB of 117.
- **Unverified:** whether this is all of the lag Leanne feels late in a run. The dev tests ran for minutes, not a run to the second boss. Nothing here was heard by ear. The fix is built and deployed on this machine only; it is not released, so Leanne does not have it yet.
- The maintainer's save was restored from the snapshot `before-session05-lag-test`, taken at the start of the tests (no run in progress).

## Agile retro

- **Went well:** the existing `[perf]` line already held the answer in an old dev log, so no guessing was needed. The game's own focus registry gave a cheap replacement found in the reference.
- **Did not go well:** Session 04 part 12 skipped these searches in fights only, though the same lesson (scene searches are slow) applied outside fights. The growth over time is measured but not explained.
- **Product accessibility:** no spoken text changed. Responsiveness outside fights should hold up over a run, which matters most to a screen-reader player who moves by arrows and listens for each step. WCAG 2.2 AA in spirit: no new surface; timing (2.2.x spirit, no unexpected delay) improves.
- **Session accessibility:** all work was in text: logs, code and a command file. No visual-only step. The test harness ran the game in the background and sent no input to the desktop.

## Risk analysis

- **Other lag remains late in a run** (likelihood M, impact M). Mitigation: the `[perf]` line now carries memory; ask Leanne for the log from a long session.
- **The registry misses a gated object that the old search found** (L, M). Mitigation: the only object the old search ever marked (the backpack) is in the registry; the `[assist]` line logs the gated count per change.
- **A game update renames the registry** (L, L). Mitigation: falls back to a slower search every 2 s, logged.
- Carried forward from Session 04: everything listed there, unchanged.
