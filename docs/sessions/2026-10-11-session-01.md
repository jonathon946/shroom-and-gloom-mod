# Session 01 — 2026-10-11 — project set up, sibling mods and Prism surveyed, game inspected on disk

Scope, from the maintainer's request: set up the project to the tree's standards; inspect the other mod projects and the mods installed on this machine; check the Dwarf Fortress mod's Prism adoption so Prism is used here from the start; begin inspecting Shroom and Gloom.

## What we did

- Read the shared contract, the working requirements, the templates guide, the field guide and the environment notes.
- Surveyed the three sibling mod projects (Dwarf Fortress, Caves of Qud, Class of '09) for layout, house style and transferable lessons, and scaffolded this project to match the newest form (Dwarf Fortress: instructions adopted by reference, decision log in the plan, open-questions file, no TODO file).
- Surveyed the accessibility mods installed on this machine. Only two other installed games are Unity IL2CPP (Yu-Gi-Oh! Master Duel and No, I'm not a Human), both on MelonLoader 0.7.x. Four installed C# mods call Prism directly.
- Traced Prism in the Dwarf Fortress mod: introduced in its Session 18 (2026-10-10), v0.18.3, through a C shim because DFHack's Lua has no FFI. Correction to the request's premise: Tolk was planned there but never shipped, so Prism replaced the plan, and NVDA still goes through NV Access's own client there because Prism's NVDA backend cannot report "still speaking".
- Inspected the game on disk without launching or changing it. Details in [the reconnaissance record](../recon-2026-10-11.md).
- Wrote `tools/Dump-MetadataNames.ps1` and ran it.
- Created the repository and the hub entry.

## Confirmed by ear / verified by data / unverified

- **Confirmed by ear:** nothing; there is no product yet.
- **Verified by data:** engine and build facts; the class and file names; the loader, speech and Prism details of the installed mods (from their files, logs and decompiled declarations); the Prism header and the Dwarf Fortress binding.
